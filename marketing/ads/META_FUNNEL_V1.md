# Meta 전환 퍼널 v1 — 구현 기록과 광고 초안 명세

브랜치: `feat/meta-conversion-funnel-v1`
작성일: 2026-08-19

원본 지시문의 랜딩 URL은 경쟁사(foxbunny.io)였다. 남의 도메인은 수정할 수 없으므로
**퍼널 구조만 참고해 러브레빗 자사 사이트에 구현**했다. 상품 매핑은 아래와 같다.

| 지시문 랜딩 | 러브레빗 라우트 | 연결 상품 | 가격 |
|---|---|---|---|
| 이별결정 (`breakup_decision`) | `/saju/breakup-decision` | `ibyeol` 이별 부검 리포트 | 29,900원 |
| 속마음 (`inner_mind`) | `/saju/inner-mind` | `sseom` 썸 해부 사주 | 12,900원 |

`inner_mind`는 폭스바니의 '심안(속마음)'에 1:1 대응하는 상품이 없어 **상대 심리 추적** 티어에서
가장 가까운 `sseom`으로 붙였다. 다른 상품이 맞다면 `src/lib/meta-events.ts`의
`LANDING_BY_PRODUCT` 한 줄만 고치면 된다.

## 1. 구현된 것

### 이벤트 (`src/lib/meta-events.ts`)

| 이벤트 | 발화 지점 | 파라미터 |
|---|---|---|
| `PageView` | 모든 화면 (SPA 라우팅 포함) | 없음 |
| `ViewContent` | 두 랜딩 진입 | `content_name` |
| `PreviewStarted` | 랜딩 CTA 클릭 | `landing_type` |
| `CompleteRegistration` | `auth/complete` 로그인 완료 | `method` (제공자명만) |
| `SajuFormStarted` | `/reading` 생년월일 첫 입력 | `landing_type` |
| `SajuFormCompleted` | `/reading` 제출 → 생성 시작 | `landing_type` |
| `PreviewGenerated` | `/reading/generating` 생성 완료 | `landing_type` |
| `ResultUnlockClicked` | `/reading/[id]` 잠금 해제 CTA | `landing_type` |
| `InitiateCheckout` | 결제 모달 진입 | `value`, `currency`, `landing_type` |
| `Purchase` | 결제 승인 성공 | `value`, `currency`, `transaction_id`, `event_id` |

`SajuFormStarted`는 생년월일 칸에 첫 값이 들어간 순간 ref 가드로 한 번만 발화한다.

`landing_type`은 광고 랜딩과 연결된 상품(`ibyeol`, `sseom`)일 때만 붙는다. 자연 유입 리딩은
커스텀 이벤트를 발송하지 않아 광고 데이터가 오염되지 않는다.

### 중복 제거
`Purchase`는 클라이언트 Pixel과 서버 CAPI(`/api/meta/capi`)가 **같은 `event_id`**로 각각 한 번씩
보낸다. Pixel이 차단된 브라우저에서도 전환이 남는다.

### 개인정보 보호
- 광고로 나가는 값은 금액·통화·주문번호·`landing_type`·로그인 제공자명뿐이다.
- 생년월일·출생시간·출생지·성별·상대방 정보·관계 상황 원문·사주 결과·결제수단은 전송하지 않는다.
  CAPI 라우트는 화이트리스트 밖 필드를 요청에서 받아도 버린다.
- 속마음 랜딩의 상황 선택값은 `sessionStorage`에만 남고 URL·이벤트에 들어가지 않는다.
- 쿠키 동의 전에는 Pixel `<script>` 자체가 주입되지 않는다.

### 신규 화면
- `/saju/breakup-decision` — 지시문 카피 그대로. 히어로 CTA + 하단 고정 CTA + 결과물 카드 4종.
- `/saju/inner-mind` — 도입 연출 → 상황 선택 → 미리보기. 자동재생 오디오 없음, 스킵 버튼이
  같은 설문에 도달. 접근성용 `h1` 유지.
- `/privacy` — 개인정보처리방침. 사업자 정보·연락처는 운영자가 채워 넣었다(20cb2e9, a70181f).

### 검증 완료
- `npx tsc --noEmit` 통과, `npm run build` 통과.
- 동의 전: `fbq` 미정의, Pixel 스크립트 미주입, 배너 노출 확인.
- 동의 후: 배너 사라짐. Pixel ID 미설정이라 스크립트는 여전히 미주입(의도된 동작).
- CAPI 미설정 시 `{"skipped":"not_configured"}` 200 반환 — 결제 플로우를 막지 않음.
- 375px / 768px 가로 오버플로 없음.

### 자동 고급 매칭 — 코드로 차단함

설정 화면에서 이 데이터 세트의 자동 고급 매칭이 켜져 있고, 수집 항목에
**생년월일과 성별**이 포함되어 있었다. `/reading` 폼에 정확히 그 입력이 있어,
그대로 두면 Pixel이 방문자의 생년월일·성별을 해시해 Meta로 보낸다 — 지시문 5번 위반.

대시보드 토글은 자동화 클릭에 반응하지 않아(신뢰된 제스처 필요), 대신 코드에서
`fbq('set', 'autoConfig', false, ...)`를 init 앞에 넣어 차단했다. 데이터 세트 설정보다
확실한 방법이고, 자동 버튼 클릭 감지도 함께 꺼진다(모든 이벤트를 명시 발송하므로 불필요).

### 검증 (로컬)
- 동의 전: Pixel 스크립트 미주입 / 동의 후: `fbevents.js` 로드, `fbq.loaded=true`
- `PreviewStarted` → `{landing_type: "breakup_decision"}` 발화 확인
- `SajuFormStarted` → `{landing_type: "breakup_decision"}` 만 발화, 생년월일 값 없음 확인
- 생년월일 3칸 연속 입력에도 1회만 발화 (ref 가드 정상)

### 아직 막힌 것 — 전환 API 토큰
`설정 → 전환 API → 액세스 토큰 만들기`가
**"필수 조건 누락 — 액세스 토큰을 만들려면 이 비즈니스 포트폴리오의 관리자여야 합니다"**

토큰이 없어도 클라이언트 Pixel 추적은 정상 동작하고, `/api/meta/capi`는
`{"skipped":"not_configured"}`를 돌려주며 결제 플로우를 막지 않는다.
토큰이 생기면 `META_CAPI_ACCESS_TOKEN`만 채우면 서버 전환까지 켜진다.
## 2. 광고 초안

Ads Manager 접근은 확인했다(`act=1501156981218798`, 활성 캠페인 2개).
그러나 두 캠페인 모두 목표가 **Sales / 전환 위치 Website**라 **Pixel(Dataset)이 반드시 필요한데,
현재 이 광고 계정에 연결된 Pixel이 코드에도 환경변수에도 없다.**

지시문의 "새 Pixel을 임의 생성하지 않는다" 제약에 따라 Pixel 생성은 하지 않았다.
아래 순서로 사람이 한 번만 처리하면 광고 초안 생성으로 넘어갈 수 있다.

1. Events Manager → 데이터 소스 → Pixel 생성 (또는 기존 Pixel ID 확인)
2. Vercel 환경변수에 `NEXT_PUBLIC_META_PIXEL_ID`, `META_PIXEL_ID`, `META_CAPI_ACCESS_TOKEN` 입력
3. 이 브랜치 배포 후 Events Manager 테스트 이벤트로 퍼널 발화 확인
4. 그 다음에 아래 초안 스펙대로 캠페인 생성

> **경고:** 현재 활성 캠페인 2개가 전환 이벤트 없이 구매 목표로 집행 중이다.
> 최적화 신호가 없는 상태라 예산이 학습 없이 소모된다. Pixel 연결을 최우선으로 볼 것.

### 전환 이벤트 — 명세와 다르게 설정한 이유

명세는 `PreviewGenerated`를 요구했으나 **Meta 목록에 없었다.** 커스텀 이벤트는 실제로 수신된 적이
있어야 선택 가능한데, `PreviewGenerated`는 로그인 후 리딩 생성까지 가야 발생해 아직 0건이다.

대신 실제 수신된 커스텀 이벤트(`PreviewStarted`, `SajuFormStarted`) 중 퍼널상 가장 깊은
`SajuFormStarted`로 맞춤 전환을 만들어 연결했다.

- 맞춤 전환: **`CC_SajuFormStarted_V1`** (ID `916789188150603`)
- 규칙: URL 포함 `c=ibyeol` — 이별결정 퍼널로만 범위 제한
- 상태: 생성 직후라 "수신된 활동 없음". 트래픽이 들어오면 활성화된다.

**게시 전에 바꿔야 한다.** `PreviewGenerated`가 쌓이면 그것으로, 최근 14일 Purchase가 50건을
넘으면 `Purchase`로 교체하는 것이 원래 설계다.

### 연령 상한을 못 건 이유

Advantage+ 타겟 모드에서는 **최소 연령만** 지정할 수 있다. 명세의 20–44 중 하한 20만 적용했고
상한 44는 이 모드에서 강제할 수 없다. 예상 타겟 규모는 26,300,000–30,900,000.

### 크리에이티브 — 자동화로 못 올림

`marketing/ads/meta-policy-v1/relationship-decision-ad-*` 가 이 랜딩에 정확히 맞는 소재다
(배지 "관계 결정 리포트", CTA "무료 관계 판정 시작하기" — 랜딩 카피와 일치).

## 2-C. 자동화로 끝내지 못한 것과 그 이유

세 항목은 여러 방법을 시도했으나 Meta 쪽 제약으로 막혔다. 추측이 아니라 실제로 시도한 결과다.

### 크리에이티브 업로드 — 세 가지 방법 모두 실패
1. `file_upload` 도구 → 페이지에 `input[type=file]`이 아예 없음 (0개)
2. 업로드 버튼 프로그래매틱 클릭 → 입력 요소가 DOM에 생성되지 않음
3. `DataTransfer`로 drag-and-drop 이벤트 합성 → 미디어 창이 반응하지 않음 (선택 0개 유지)

Meta는 네이티브 파일 선택창만 사용한다. 광고 문구·헤드라인 입력란도 미디어를 고른 뒤에만
열리므로 카피까지 함께 대기 상태다.

### 전환 API 토큰 — 권한 구조 문제
`액세스 토큰 만들기`가 "이 비즈니스 포트폴리오의 관리자여야 합니다"로 비활성.
비즈니스 관리자를 확인해 보니 포트폴리오가 2개 있는데
(`Shopify: bysstore...`, `stuple_0000`) **둘 다 광고 계정 0개**다.
즉 광고 계정 `1501156981218798`이 어느 포트폴리오에도 속해 있지 않다.

해결하려면 광고 계정과 픽셀을 포트폴리오로 옮겨야 하는데, 이는 소유권·청구·권한에 영향을 주고

### 새 계정의 가치 (세션 문제와 별개)

`loverabbit-ads`는 옛 계정이 포트폴리오 밖에 있던 별개의 실제 문제를 해결했다.
포트폴리오 소속·KRW·Asia/Seoul·픽셀 연결·결제수단 등록이 모두 끝나 있으므로,
API 세션만 정상화되면 곧바로 전환 캠페인을 구성할 수 있다.
